# Out-of-Spec Ideas

This file is the landing place for ideas that go beyond the current spec (§0.4).
Record an idea here rather than implementing it. Ideas are reviewed when a new spec version is
drafted or a stage is planned.

## Ideas

- **Fast-tier JS/TS linter (Biome or Oxlint):** If ESLint's fast-path performance misses its
  p95 < 2 s budget, consider adding Biome or Oxlint as a tier-F alternative that runs without
  type information. Per §12 D6, ESLint + typescript-eslint is the confirmed choice; this would
  be a supplementary fast pass, not a replacement.

- **C/C++ language tier (deferred, D15):** Meaningful static analysis for C/C++ requires
  `compile_commands.json` (generated by cmake, meson, or bear). Purely syntactic Opengrep
  rules would give false confidence because user-defined types and preprocessor macros make
  patterns non-compositional. Revisit when the plugin matrix includes a compile-commands-aware
  adapter (e.g. clang-tidy driven by `compile_commands.json`). Until then, C/C++ files are
  detected by `stacks.json` but carry no Opengrep rules and no skill — the detector exits
  cleanly with no coverage rather than noisy false positives.

- **`osv-scanner`-based multi-ecosystem SCA (Stage 4 follow-up, D16):** `osv-scanner` covers
  ecosystems that `composer audit`, `govulncheck`, `npm audit`, and `pip-audit` do not —
  including Cargo (Rust), Maven/Gradle (JVM), NuGet (C#), and RubyGems. It is the natural
  SCA tool for tier-2 languages and will be added to `tools.lock.json` together with the Stop
  gate handler in Stage 4. Not added now because the Stop gate (`hooks/hooks.json` entry +
  handler) does not yet exist; pinning an uncalled binary wastes an install slot.
